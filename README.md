# 防诈守门人 · 适老化 AI 陪伴产品设计

>用户体验设计课程实践作业｜以人为本的 AI 陪伴产品包容性创新设计

一份面向 **60–75 岁独居老人**的 AI 陪伴产品设计方案。核心主张：把 AI 陪伴从「提供情绪价值」推进到「承担风险防护」——这是当前主流 AI 陪伴产品尚未覆盖的真空地带。

## 设计背景

### 目标用户

| 维度 | 描述 |
|---|---|
| 年龄 | 60–75 岁 |
| 居住状态 | 独居，子女异地工作 |
| 数字能力 | 会用微信语音通话，但对复杂 App 操作存在明显障碍 |
| 风险特征 | 独处时间长、社交面窄、涉诈骗风险高、对金融术语不敏感 |

### 现有产品障碍

通过对主流 AI 陪伴类产品的界面结构与交互路径拆解，归纳出四类系统性障碍：

| 障碍 | 具体表现 | 影响 |
|---|---|---|
| **视觉可读性不足** | 正文字号普遍为 11–13px，信息层级嵌套超过 3 层，图标缺少文字标签 | 老人需要主动凑近屏幕辨认，或干脆放弃 |
| **语音识别不友好** | 唤醒词对带口音的老人识别率低，误唤醒频繁 | 交互挫败感累积，最终放弃语音功能 |
| **风险判断缺失** | AI 对来电身份无判断能力，全行业无资金/转账类请求的拦截机制 | 诈骗发生率高，且缺少兜底手段 |
| **陪伴感被动** | 需用户主动提问才响应 | 从「陪伴者」退化为「工具」，情感价值无法建立 |

其中**第三项是本方案的主攻方向**——现有产品普遍把 AI 陪伴定位为情感工具，没有任何一层针对资金风险的防护设计。

## 方案三件套

### 01　防诈三问确认

不直接替老人判断对错，而是把「这是不是诈骗」拆解成三个是非题，让老人自己得出结论。

- 触发条件：涉及转账、验证码、身份证信息时强制介入
- 界面处理：第三问做视觉弱化（浅底色、无描边），降低认知负荷
- 兜底机制：同步通知家属，5 分钟未处理自动拨打家属电话

> **设计论证**：单纯做「拦截」会被追问漏判怎么办，讲「三问确认」逻辑自洽——AI 不替代判断，而是**帮用户把判断撑开**。这既保留了人的主体性，又在认知能力下降时提供足够支撑。

### 02　主动式陪伴

不依赖老人主动提问，AI 按作息主动发起关怀：晨间天气 + 用药提醒、午间问候、晚间复盘。

- 一屏一意图，把「今天要做什么」一次性讲清
- 主操作按钮高度 72px，图标与文字并置（老人不需要学习图标语言）

### 03　家属可见陪伴日志

家属端仅显示 AI 生成的摘要——风险事件、用药完成、情绪概况三条，**不呈现原始对话**。

```
✓ 可介入 —— 家属可在需要时立即回拨、下钻查看详情
✗ 不越权 —— 私人对话内容永不暴露
```

> **伦理落点**：这个方案的终点不是「让子女监控母亲」，而是**可介入，但不越权**。该边界在界面上以常驻说明的形式明确表达，防止方案被误读为监控工具。

## 原型演示

`index.html` 是一个可交互原型，包含三屏完整闭环：

| 屏幕 | 场景 | 演示要点 |
|---|---|---|
| **S1 日常陪伴** | 07:30 起床后 | AI 主动问候，无需用户任何操作 |
| **S2 风险拦截** | 14:20 可疑来电 | 三问确认 + 家属通知兜底 |
| **S3 家属介入** | 14:26 女儿视角 | 摘要日志 + 立即回拨 |

### 界面展示

| S1 · 日常陪伴 | S2 · 风险拦截 | S3 · 家属介入 |
|---|---|---|
| <img src="docs/images/s1-home.png" width="260" alt="S1 老人端主页"> | <img src="docs/images/s2-fraud.png" width="260" alt="S2 反诈拦截确认"> | <img src="docs/images/s3-family.png" width="260" alt="S3 家属端陪伴日志"> |

> 图片为 Ardot 设计稿 2x 导出，与 `index.html` 原型 1:1 一致。

### 交互方式

- 底部标签或左右箭头切换屏幕，键盘 `←` `→` 或数字键 `1` `2` `3` 亦可
- **点击「我挂断了，请帮我」→ 红框闪烁 + 自动跳转家属端**，完整演示风险闭环
- 底部「显示无障碍标注」开关：叠加字号层级、触控区尺寸、语义色说明，用于讲解无障碍设计依据
- 右侧场景面板随屏幕切换同步更新设计决策

| 20px | 辅助说明 |
| 17px | 次要提示（系统下限） |

## 无障碍设计依据

| 原则 | 落地方式 |
|---|---|
| **看得清** | 最小正文 20px（远高于常规 14px），图标必配文字标签 |
| **点得准** | 最小触控区 64px，实际主按钮 72px，相邻按钮间距 14px 防误触 |
| **想得少** | 一屏一意图，可选项不超过 3 个，第三问视觉弱化 |
| **拦得住** | 资金类请求强制三问复述，AI 不代为操作 |
| **守得住** | 家属仅见摘要，隐私边界在界面常驻说明 |

## 学术诚信说明

本项目为用户体验设计课程实践作业。

- 设计过程遵循以人为本（Human-Centered Design）方法：用户研究 → 障碍分析 → 方案设计 → 原型验证
- 原型使用 AI 辅助生成，视觉方案与设计决策由本人完成
- 文案中的用户数据为基于公开资料与典型场景构建的**示例性人物（Pseudo-persona）**，非真实用户研究结论
- 若用于学术提交，请根据实际要求补充真实的用户访谈与可用性测试记录
